# Фаза 3 (PLANNING) — артефакты профиля `compact`

> Профиль `docs=compact|full` (дефолт `compact`). Полный профиль — `reference.artifacts.full.md`.

Принцип `compact`: dev-task — основной потребляемый артефакт implementation, создаётся всегда. Сводный dev-plan — компактный индекс-таблица без нарратива.

## Состав артефактов

| Артефакт | Профиль `compact` | Формат | Обязательные секции |
|---|---|---|---|
| dev-task (на логический срез) | ✅ всегда | проза + checklist | `## Цель` · `## Входные условия` · `## Зависимости` · `## Шаги реализации` · `## Тест-кейсы` · `## Acceptance Criteria` · `## Выходные артефакты` |
| dev-plan (сводный) | ✂️ компактный индекс | таблица | таблица dev-task (№·название·зависит от·файлы); порядок/зависимости |
| future-task | ✅ если есть техдолг вне scope | по `rule.governance.ru.future-tasks` | — |
| dev-process-plan | ✅ обновляется | таблицы | — |

## Что опускается/усекается в `compact`

- Нарративные описания в dev-plan (обоснования, контекст «зачем») — заменяются ссылками на dev-task.

## Незыблемое

dev-task создаются всегда и в полном объёме (нужны implementation): acceptance criteria конкретны и проверяемы, тест-кейсы прописаны, шаги однозначны.
