# Окружения интеграции: <[Система A] ↔ [Система B]>

## Таблица 1. Окружения систем

| N | Система | Окружение | URL / инстанс | Активно в интеграции? | Примечание |
|---|---|---|---|---|---|
| 1 | [Система A] | TEST | <!-- https://a-test.example.com --> | да | |
| 2 | [Система A] | PROD | <!-- https://a.example.com --> | да | |
| 3 | [Шлюз] | TEST | | да | |
| 4 | [Шлюз] | PROD | | да | |
| 5 | [Система B] | PROD | | да | один инстанс на test+prod |
| 6 | [Система B] | (QA-инстансы) | | нет | группа инстансов |

Колонки: `Окружение` ∈ TEST/STAGE/PRE-PROD/PROD/DEV или системные коды (HRD/HRP/QAS). `Активно?` = участвует ли в данной интеграции.

## Таблица 2. Связи окружений

Какое окружение к какому подключается. Учитывай нюансы: несовпадение количества, тестовые/продовые инстансы в одном окружении.

| N | Окружение-источник | Окружение-приёмник | Тип маппинга | Примечание |
|---|---|---|---|---|
| 1 | [Система A] TEST | [Шлюз] TEST → [Система B] PROD | many:1 | TEST маппится на «тестовую компанию» в едином PROD-инстансе [Системы B] |
| 2 | [Система A] PROD | [Шлюз] PROD → [Система B] PROD | 1:1 | продовый поток |

Тип маппинга: `1:1` (совпадающие тиры) / `many:1` (коллапс в один инстанс) / `диагональ` (DEV→TEST и т.п.).

> Эту таблицу заполняет пользователь самостоятельно или с поддержкой отдела архитектуры — из-за специфики окружений. Первый столбец всегда `N`.
