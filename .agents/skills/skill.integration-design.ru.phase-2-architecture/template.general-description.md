## Тех-таблица связей

Главный источник истины для агентов. Каждая строка — одна направленная связь (кто вызывает кого).
Технологии фиксируй детально: вызываемый эндпоинт/операция, описание, формат данных, тип взаимодействия, модель аутентификации, протокол/транспорт.

| N | Источник | Приёмник | Эндпоинт / операция | Описание | Формат данных | Тип взаимодействия | Модель аутентификации | Протокол/транспорт | Частота | Направление | Комментарий |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 1 | [Система A] | [Шлюз] | `POST /v1/orders` | передача заказа в обработку | JSON | REST | OAuth2.0 client_credentials через OAuth2.0 Access Token Provider | HTTPS | по событию | синхронный, PULL | |
| 2 | [Шлюз] | [Система B] | `POST /api/orders` | создание заказа в целевой системе | JSON | REST | Basic Auth | HTTPS | по событию | синхронный, PUSH | |
| 3 | [Система B] | [Шлюз] | `GET /odata/Status` | опрос статуса | XML | OData | API key | HTTPS | периодически | асинхронный | трансформация ответа на шлюзе |

### Описание колонок

| Колонка | Значение |
|---|---|
| **N** | Порядковый номер связи |
| **Источник** | Система-инициатор вызова |
| **Приёмник** | Вызываемая система |
| **Эндпоинт / операция** | Какой эндпоинт/метод/операция вызывается (`POST /v1/orders`, имя gRPC-метода, имя события). Полное описание эндпоинтов — в `api-endpoints` |
| **Описание** | Зачем выполняется вызов (бизнес-смысл связи) |
| **Формат данных** | `JSON` / `XML` / `multipart/form-data` / `application/pdf` / `IDocs` / иное |
| **Тип взаимодействия** | `REST` / `gRPC` / `OData` / `SOAP` / `RFC` / иное |
| **Модель аутентификации** | `OAuth2.0 client_credentials (OAuth2.0 Access Token Provider или иной Identity Provider)` / `Basic Auth` / `mTLS` / `API key` |
| **Протокол/транспорт** | `HTTPS` / `HTTP` / `AMQP` / `TCP/IP` |
| **Частота** | `по событию` / `периодически (cron)` / `по запросу` / `потоково` |
| **Направление** | `синхронный/асинхронный` + паттерн `PULL` / `PUSH` / `POLL` |
| **Комментарий** | Прочие особенности: заголовки, ограничения, функции шлюза (кэширование, маршрутизация) |

> Первый столбец всегда `N`, последний — `Комментарий`. На основе этой таблицы формируется C2 (`reference.c2-requirements`). Эндпоинты раскрываются детально в `api-endpoints`, преобразования полей — в `field-mapping`.

### Правила надёжности (база)

- **Таймаут** обязателен для каждого внешнего вызова (рекомендуемый предел ≤ 30 000 ms).
- **Retry** с экспоненциальной задержкой для идемпотентных операций (база: 3 попытки, 1s/2s/4s).
- **Circuit breaker** для критичных сценариев.
- Логирование — структурное, **без ПДн/секретов**.
