# Описание перечисления

Стандарт документирования перечислений (enum / discriminated union): фиксирует все допустимые значения, их системные имена, сериализованные значения и бизнес-смысл.

**Смежные скиллы:**
- `skill.dev.ru.data-model-table` — таблица модели, где перечисление используется как тип (`enum` в колонке «Формат»).
- `reference.md` — расширенные примеры, анти-паттерны, версионирование и краевые случаи по стеку.
**Приоритет:** явные инструкции пользователя → этот скилл → общая эвристика.

## Когда применять

- Документирование любого `enum` или `record`-перечисления в .NET (или аналогов в других стеках).
- Описание дискриминантов в API-контрактах и интеграционных паспортах.
- Описание справочных значений в схемах БД.
- Любой контекст, где набор допустимых значений нужно зафиксировать формально.

## Шаблон описания перечисления

### Название перечисления (EnumName)

**Тип реализации:** `<enum (int)>` | `<record (string)>` | `<иное — указать>`

*Пример заполнения:*

| N | Системное название | Значение | Название | Комментарий |
|---|---|---|---|---|
| 1 | `Undefined` | `0` | Не определено | Резервное значение по умолчанию; не передавать явно |
| 2 | `Active` | `1` | Активный | Запись участвует в расчётах и доступна пользователям |
| 3 | `Suspended` | `2` | Приостановлен | Временно недоступен; может быть переведён обратно в Active |
| 4 | `Deleted` | `3` | Удалён | Мягкое удаление; не отображается в UI |

---

## Описание колонок

| Колонка | Описание |
|---|---|
| **N** | Порядковый номер строки для навигации. |
| **Системное название** | Название свойства в коде. Зависит от стека: `.NET` — `PascalCase`. Для межсервисных контрактов и БД по корпоративной конвенции используется именно это значение (см. MUST/SHOULD-правила ниже). |
| **Значение** | Сериализованное значение: целое число для `enum (int)`, строка для `record (string)`. |
| **Название** | Человекочитаемое название для документации и UI. |
| **Комментарий** | Бизнес-смысл значения: когда используется, ограничения, особенности поведения. |

> Первый столбец всегда `N`, последний всегда `Комментарий`.

## Тип реализации

Указывается один раз на уровне документа — над таблицей. Определяет, что попадает в колонку «Значение».

| Тип реализации | Колонка «Значение» | Пример |
|---|---|---|
| `enum (int)` | Целое число | `0`, `1`, `2` |
| `record (string)` | Строковый литерал | `"undefined"`, `"active"` |
| Иное | Указать явно | — |

## Обязательные правила

### Сериализация в БД и межсервисном взаимодействии

Для межсервисного взаимодействия **MUST** передавать стабильное сериализованное значение, согласованное в контракте (предпочтительно строковое системное имя).

Для БД действует проектная конвенция: **SHOULD** хранить строковое системное имя (`Системное название`) даже для `enum (int)`.

Техническое уточнение для .NET/EF Core: по умолчанию `enum (int)` сохраняется как число; строковое хранение требует явной настройки ORM (`HasConversion<string>()`).

> Пример: значение `Active` хранится в БД как строка `"Active"`, а не как `1`.

### Правило нулевого значения для `enum (int)`

Для целочисленных `enum` значение `0` **MUST** обозначаться как `Undefined`. Это предотвращает случайную передачу неинициализированного значения по умолчанию.

> Если логика домена не предполагает состояния «не определено» — `Undefined` всё равно объявляется, но запрещается к использованию (фиксируется в Комментарии).

Исключение для `[Flags]`-enum: допускается альтернативная нулевая семантика (`None = 0`) вместо `Undefined = 0`, если это прямо отражает битовую модель и зафиксировано в комментарии/документации.

### Версионирование enum в межсервисных контрактах

- **MUST NOT** менять сериализованное значение у уже опубликованных элементов.
- **MUST NOT** переиспользовать удалённые/устаревшие значения для новых смыслов.
- **SHOULD** добавлять новые значения в конец перечисления.
- Удаление опубликованного значения допускается только с миграционным планом и явным описанием обратной совместимости.

## Соглашения именования

| Контекст | Системное название | Значение |
|---|---|---|
| .NET `enum` | `PascalCase` | `int` (`0`, `1`, `2`) |
| .NET `record` | `PascalCase` | строка (`"Active"`) |
| TypeScript `enum` | `PascalCase` | `number` или `string` по типу enum |
| TypeScript string literal union | `camelCase` или `PascalCase` по контракту | строка (`"active"`, `"suspended"`) |
| Python `Enum`/`StrEnum` | `UPPER_SNAKE_CASE` (имя элемента) | `int` или `str` по реализации |
| Другой стек | Определяется соглашением проекта | Определяется соглашением проекта |

## Перед сдачей (чеклист)

- [ ] Указан «Тип реализации» над таблицей.
- [ ] Первый столбец — `N`, последний — `Комментарий`.
- [ ] Для `enum (int)` значение `0` обозначено как `Undefined`.
- [ ] Для `[Flags]`-enum явно зафиксирована нулевая семантика (`None = 0` или эквивалент) и причина отклонения от `Undefined`.
- [ ] Колонка «Значение» содержит только числа (int) или строки (record) без лишних описаний.
- [ ] Для каждого значения заполнен «Комментарий» с бизнес-смыслом.
- [ ] Именование в «Системное название» соответствует стеку (`PascalCase` для .NET).
- [ ] Если `Undefined` объявлен только как технический guard и не используется доменно — в колонке «Комментарий» явно указано «Не использовать».
- [ ] Если enum используется в модели — в `skill.dev.ru.data-model-table` в колонке «Формат» указано имя этого enum.
