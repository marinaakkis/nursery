# Структура папок модуля — справка

## Пример дерева

```text
<project-name>-<project-type>/
  .input/                         # опционально, в .gitignore
    technical-specification.md
    api-draft-openapi.yaml        # черновик; итоговый контракт — в docs/api-requirements/
    ... черновые материалы до начала работы с требованиями ...
  docs/
    README.md
    architecture-overview.md
    requirements-matrix.md
    api-requirements/
      api.<project-name>.<domain>.md   # итоговый API-контракт (из черновика в .input/)
      api.external.<system-name>.md    # контракт внешней интеграции
    ... шаблон и имена — по политике репозитория ...
```

## Значения `project-type` (ориентир)

| Значение | Когда уместно |
|----------|----------------|
| `utility` | Вспомогательный инструмент, скрипт, конвертер. |
| `service` | Фоновый или сетевой сервис, API backend. |
| `application` | UI-приложение, десктоп или web-клиент как продукт. |
| `system` | Несколько частей как единая система в одном модуле. |
| `module` | Фрагмент платформы без самостоятельного «продукта». |
| `library` | Переиспользуемый пакет кода/данных. |
| `tool` / `cli` | Утилита командной строки (если хотите отличать от `utility`). |

Имя типа — **соглашение команды**; главное — одно понятное слово и единообразие в монорепозитории.

## `docs/` не ссылается на `.input/`

В markdown-файлах каталога **`docs/`** не используют ссылки (относительные или иные), указывающие на **`.input/`**. Итоговая документация остаётся самодостаточной; путь к ТЗ и черновикам агент или README модуля указывают вне тела файлов `docs/`. Исключение — только если репозиторий явно ослабил правило.

## API-требования и контракты

Требования к API-контрактам, межсервисному взаимодействию и интеграционным интерфейсам размещай в:

- `docs/api-requirements/`

Именование:

- Внешние интеграции: `api.external.<system-name>.md`
- API текущего сервиса: `api.<project-name>.<domain-or-service-or-controller-name>.md`

Технические ограничения для сегментов имени:

- Только lowercase `kebab-case` (`a-z`, `0-9`, `-`).
- Без пробелов, подчеркиваний и кириллицы.

## Дополнительные соглашения репозитория

Команда может отдельно зафиксировать: имена файлов спецификации, шаблоны `docs/`, опросы стейкхолдеров, чеклисты — **это не часть** скилла `project-folder-layout`. Такие файлы, если они считаются **черновыми исходными материалами**, логично держать в `.input/`; если это **производные** записи после воркшопов, согласуйте с командой (`docs/` vs `.input/`).

## Монорепозиторий с несколькими модулями

Каждый модуль — отдельный каталог верхнего уровня (или под согласованным корнем `packages/`, `services/`), внутри которого снова **`.input/`** (опционально) и **`docs/`**. Не смешивай `.input` одного модуля с `docs` другого.
