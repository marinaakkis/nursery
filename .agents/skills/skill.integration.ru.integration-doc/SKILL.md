# Описание интеграционного взаимодействия

Стандарт документирования взаимодействия между двумя системами: протокол, аутентификация, надёжность и перечень вызываемых эндпоинтов.

**Уровни документирования интеграций:**
- Этот скилл — **обзорное описание взаимодействия**: что вызывается, как, с каким паттерном.
- Полный паспорт — `docs/integrations/integration-passport.{name}.md` по шаблону `.agents/skills/skill.integration.ru.integration-doc/template.integration-passport.md`: метаданные, мониторинг, контакты, ПДн, changelog.

**Смежные скиллы:**
- `skill.integration.ru.api-endpoint-doc` — детальное описание одного эндпоинта (параметры, тело, статусы).
- `skill.dev.ru.data-model-table` — описание модели запроса / ответа.
- `reference.md` — примеры заполнения для не-HTTP протоколов и входящего webhook.

**Приоритет:** явные инструкции пользователя → этот скилл → общая эвристика.

## Когда применять

- Документирование вызовов между двумя сервисами в архитектурных артефактах.
- Описание интеграционного взаимодействия в интеграционном паспорте (раздел «Эндпоинты»).
- Обзорный реестр вызовов в рамках одной интеграции.
- Подготовка интеграционной документации в фазах DESIGN и IMPLEMENTATION, когда требуется зафиксировать контур вызовов.

| Параметр | Значение |
|---|---|

## Описание колонок таблицы эндпоинтов

| Колонка | Описание |
|---|---|
| **N** | Порядковый номер строки. |
| **Метод / Операция** | Для HTTP: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`; для gRPC: RPC-метод; для брокеров сообщений: операция (`Publish`, `Subscribe`). |
| **Путь** | Путь эндпоинта, например `/api/v1/users/{userId}`. |
| **Описание** | Что делает вызов и зачем он нужен в контексте интеграции. |
| **Content-Type запроса** | MIME-тип тела запроса. `—` если тела нет (GET, DELETE без тела). |
| **Content-Type ответа** | MIME-тип тела ответа. `—` если тела нет (204, async fire-and-forget). |
| **Тип вызова** | Паттерн взаимодействия (см. справочник ниже). |
| **Комментарий** | Особенности, ссылки на детальное описание, ожидаемые успешные/ошибочные статусы, особенности надёжности для конкретного эндпоинта. |

> Первый столбец всегда `N`, последний всегда `Комментарий`.

## Типы вызова — справочник

| Значение | Описание | Пример |
|---|---|---|
| `sync-pull` | Синхронный, инициатор запрашивает данные | REST GET по расписанию или по запросу пользователя |
| `sync-push` | Синхронный, инициатор отправляет данные и ждёт подтверждения | REST POST при создании сущности |
| `sync-polling` | Синхронный, периодический опрос | REST GET каждые N секунд; указывай частоту: `sync-polling (1/min)` |
| `async` | Асинхронный, ответ не ожидается немедленно | Публикация в очередь, входящий webhook (`ВнешняяСистема → НашаСистема`) |

## Перед сдачей (чеклист)

- [ ] Заголовок содержит названия обеих систем в формате `Инициатор → Обработчик`.
- [ ] Указан протокол взаимодействия.
- [ ] Заполнен раздел «Аутентификация и авторизация».
- [ ] Заполнен раздел «Надёжность»: таймаут, retry, circuit breaker.
- [ ] В таблице эндпоинтов каждая строка имеет заполненное «Описание» и «Тип вызова».
- [ ] «Тип вызова» содержит только значения из справочника; для `sync-polling` указана частота.
- [ ] `Content-Type` = `—` там, где тела нет (GET без тела, 204, async fire-and-forget).
- [ ] В «Комментарий» по каждому эндпоинту указаны ожидаемые успешные/ошибочные статусы или ссылка на документ по `skill.integration.ru.api-endpoint-doc`.
- [ ] Для детального описания конкретных эндпоинтов есть ссылка или отдельный документ по `skill.integration.ru.api-endpoint-doc`.
- [ ] Если интеграция новая — создан или обновлён полный паспорт в `docs/integrations/`.
- [ ] Если интеграция новая или изменена — создан или обновлён `docs/integrations/integrations-log.{project-name}.md`.
