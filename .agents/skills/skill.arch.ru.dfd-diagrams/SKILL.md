# DFD-диаграммы — нотация dfd.*

Дефолтная нотация: **Gane-Sarson**. Если задача требует Yourdon-DeMarco — укажи явно в комментарии к диаграмме.

**Приоритет:** явные инструкции пользователя и правила репозитория → этот скилл → общие визуальные предпочтения.

## Когда применять

- Нужно показать, откуда берутся данные, как трансформируются и где хранятся.
- Нужно задокументировать потоки данных между компонентами, хранилищами и внешними субъектами.
- Задача — понять движение данных на уровне системы или отдельного модуля.

**Не применяй**, если:
- нужна техническая последовательность вызовов request/response → используй `sd.*` (`skill.arch.ru.sequence-diagrams`);
- нужен бизнес-процесс с ролями → используй `bpmn.*` (`skill.arch.ru.bpmn-diagrams`);
- нужна orchestration/saga → используй `wf.*` (`skill.arch.ru.workflow-diagrams`).

## Ключевые элементы DFD

| Элемент | Обозначение |
|---|---|
| Внешний субъект | Прямоугольник (источник/получатель данных вне системы) |
| Процесс-трансформация | Круг/эллипс (Yourdon-DeMarco) / прямоугольник с закруглёнными углами (Gane-Sarson) |
| Хранилище данных | Открытый прямоугольник / параллельные линии (Yourdon-DeMarco) / прямоугольник с именем (Gane-Sarson) |
| Поток данных | Стрелка с именем |

## Инструмент

Ни Mermaid, ни PlantUML не поддерживают DFD нативно.
Используй **Structurizr DSL** как основной инструмент. При использовании другого инструмента — укажи ограничения в комментарии к файлу.

→ Примеры синтаксиса L0/L1, сравнение нотаций, краевые случаи: [reference.md](reference.md)

## Уровни DFD

- **L0 (Context)** — система как единый процесс; внешние субъекты; основные потоки данных.
- **L1 (Detailed)** — декомпозиция системы до ключевых процессов; хранилища данных внутри системы.
- **L2+** — применяй, если процесс на L1 требует собственного хранилища данных ИЛИ содержит более 7 подпроцессов.

## Именование файлов

| Тип | Шаблон | Regex |
|---|---|---|
| DFD | `dfd.<diagram-title>.<ext>` | `^dfd\.[a-z0-9]+(?:-[a-z0-9]+)*\.[a-z0-9]+$` |

Правила:
- **(MUST)** `<diagram-title>` — только lowercase `kebab-case`.
- **(MUST)** Каждый уровень DFD — отдельный файл.
- **(MUST)** Не использовать альтернативные префиксы.
- **(MUST)** Файлы размещать в `docs/process-diagrams/`.
- **(SHOULD)** Кодировать уровень в имени файла: `dfd.l0-context.md`, `dfd.l1-payments.md`.

## Перед сдачей (чеклист)

1. Тип `dfd.*` выбран осознанно (потоки данных, не request/response или бизнес-процесс).
2. Имя файла соответствует regex `^dfd\.[a-z0-9]+(?:-[a-z0-9]+)*\.[a-z0-9]+$`.
3. Файл размещён в `docs/process-diagrams/`.
4a. Все внешние субъекты явно обозначены.
4b. Все процессы-трансформации явно обозначены.
4c. Все хранилища данных явно обозначены.
4d. Все потоки данных именованы.
5. Уровень DFD указан (L0/L1/L2 и т.д.).
6. Синтаксис диаграммы соответствует Structurizr DSL; при использовании другого инструмента ограничения задокументированы.
