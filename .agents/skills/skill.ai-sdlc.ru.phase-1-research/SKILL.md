# SKILL: phase-1-research — Фаза 1: RESEARCH

> **Скоуп:** Первая обязательная фаза любой задачи разработки. Сужает кодовую базу до минимального релевантного набора фактов AS-IS.
> **Главенствующий процессный контекст:** `rule.ai-sdlc.ru.process` — порядок фаз, гейт-правила, ролевая модель.
> **Исполнительный артефакт:** `command.ai-sdlc.ru.run-phase-1-research` содержит пошаговый алгоритм выполнения фазы (включая предварительные условия, управление контекстом разговора и механизм согласования). Этот SKILL.md — нормативная спецификация; команда — исполнительная реализация.

## Когда применять

- В начале **любой** задачи разработки (фича / баг / рефакторинг) — всегда первой
- До фазы DESIGN
- При изменении задачи, затрагивающем новые компоненты, технологии или внешние зависимости, не исследованные в текущем research — research запускается заново

## Структура research-документа

Полный шаблон со всеми разделами, полями и примерами — см. [`reference.md`](reference.md).

Разделы документа: `## Задача` / `## Затронутые компоненты` / `## Архитектурный контекст` / `## Доменные модели` / `## Внешние зависимости / интеграции` / `## Граничные условия` / `## Что не затронуто`

## Агентная структура

**Lead-агент обязан:**

1. Декомпозировать задачу на три направления исследования (Архитектура, Паттерны и доменные модели, Интеграции).
2. Запустить sub-агентов **параллельно** в независимых контекстных окнах — каждый отвечает только на своё направление:
   - **Sub-агент: Архитектура** — слои, структура, компоненты, зависимости между модулями
   - **Sub-агент: Паттерны и доменные модели** — сущности, их поля и инварианты, используемые паттерны
   - **Sub-агент: Интеграции** — вызовы внешних сервисов, API, БД, очереди
3. Собрать результаты sub-агентов и агрегировать в единый research-документ.
4. Не добавлять мнений — только синтезировать факты от sub-агентов.

> **Модели sub-агентов:** допустимо (не обязательно) использовать более дешёвые модели для поискового sub-агента, если качество выдаваемых ими фактов и ссылок на файлы достаточно для агрегации.

## Фокус по типу задачи

| Тип задачи | Основной фокус research |
|---|---|
| Новая фича | Все компоненты, которых коснётся фича; текущие интерфейсы |
| Баг | Как воспроизвести; какой код исполняется; соседние зависимости |
| Рефакторинг | Текущие паттерны; кто зависит от изменяемого кода |

## Правила research-документа

- **Только факты** — никаких советов, предложений рефакторинга, оценок качества
- **AS-IS** — описывает текущее состояние кода, не желаемое
- **Конкретные ссылки** — файл + строки, не общие описания типа "где-то в слое сервисов"
- Мнения, смешанные с фактами = шум для DESIGN → хуже качество дизайна
- **Новый проект без кодовой базы** — раздел `## Архитектурный контекст` в research-документе пропускается; в разделе `## Затронутые компоненты` указать `N/A` для всех полей «Ссылка на файл» и «Строки»
- **Обнаружены ПДн, КТ или признаки публичного API** — зафиксировать отдельной строкой `⚠ Архитектор: <описание находки>` в конце research-документа и передать сигнал в фазу DESIGN

## Гейт качества

Режим проверки задаётся в начале задачи (по умолчанию — **Режим 3**):

| Режим | Описание |
|---|---|
| **1 — Инженер** | Инженер проверяет документ вручную по чеклисту |
| **2 — Агент-ревьюер** | Отдельный агент автоматически проверяет документ по чеклисту |
| **3 — Агент + Инженер** | Агент проверяет первым, затем инженер финально верифицирует |

## Профиль артефактов (`docs`)

Состав конечных артефактов зависит от параметра `docs=compact|full` (дефолт `compact`; берётся из «Объём документации» dev-process-plan):

- **`compact`** (по умолчанию, для ИИ-агента) — research-документ только с факт-таблицами; нарративный раздел «Архитектурный контекст» опускается (при необходимости — компактным bullet-списком). Профиль: `.agents/skills/skill.ai-sdlc.ru.phase-1-research/reference.artifacts.compact.md`.
- **`full`** (человеко-читаемый) — полный research-документ со всеми разделами шаблона. Профиль: `.agents/skills/skill.ai-sdlc.ru.phase-1-research/reference.artifacts.full.md`.

В обоих профилях: правило «только факты AS-IS» и dev-process-plan не меняются.
