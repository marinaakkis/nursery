# Reference: процесс заявок на клиент и доступы

Клиенты Service-Guard и доступы между сервисами создаёт/меняет DevOps по согласованной заявке. Команда сервиса **не** правит чужие IaC-проекты напрямую — она инициирует заявку.

## К кому обращаться

| Вопрос | Куда |
|---|---|
| Создание/изменение клиента, систем и групп Service-Guard | DevOps **отдела инфраструктурного развития** + **отдел архитектуры** |
| Согласование интеграции и состава доступов — **заранее**, прежде чем запрашивать создание/изменение доступов в отделе архитектуры / инфраструктурного развития | **отдел информационной безопасности** |

## Что приложить к заявке

- Заявку на **согласование интеграции** (какой сервис, к какому, зачем, какие данные).
- Заявку на **изменение доступов** (какие роли какому клиенту выдаются/отзываются), согласованную с **отделом информационной безопасности**.
- Идентификаторы клиентов Consumer и Provider (`client_id`) и целевое окружение (`test`/`stage`/`master`).

## Что делает DevOps по заявке

1. Создаёт/обновляет описание клиента(ов) в IaC (`terragrunt.hcl`): роли и `client_system_access` — см. [reference.terragrunt.md](reference.terragrunt.md).
2. Открывает необходимые merge request'ы в проектах клиентов сервисов.
3. После применения в нужном окружении доступ появляется в токене Consumer (клейм `resource_access`).
4. Передаёт креды (`client_id`/`client_secret`) команде Consumer **безопасным каналом** (секрет-менеджер / защищённый канал), не в открытом виде.

## Последовательность для пары Consumer/Provider

1. Согласовать интеграцию и состав доступов с отделом информационной безопасности.
2. Подать заявку в отдел архитектуры / отдел инфраструктурного развития.
3. DevOps создаёт клиенты `<consumer>-service` и `<provider>-service`.
4. DevOps настраивает в `<provider>-service` доступы (`client_system_access`) для `<consumer>-service`.
5. DevOps передаёт креды команде Consumer.
6. Consumer использует креды для получения токена и вызова Provider — см. `service-guard-services-auth-process`.

## Безопасность

- Креды не передаются в чатах/почте в открытом виде; не коммитятся в репозиторий.
- При компрометации `client_secret` — заявка на ротацию через DevOps; старый секрет считать скомпрометированным.
