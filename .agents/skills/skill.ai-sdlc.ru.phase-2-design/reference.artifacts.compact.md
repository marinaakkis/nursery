# Фаза 2 (DESIGN) — артефакты профиля `compact`

> Профиль `docs=compact|full` (дефолт `compact`). Обоснование замены диаграмм таблицами: для ИИ-агента таблица плотнее и однозначнее диаграммы. Полный профиль — `reference.artifacts.full.md`.

Принцип `compact`: дизайн фиксируется таблицами решений и таблицами-эквивалентами диаграмм. **Mermaid-диаграммы не создаются.** Нарративный Design Report и `docs/architecture.md` не создаются/не обновляются.

## Состав артефактов

| Артефакт | Профиль `compact` | Формат |
|---|---|---|
| Design spec (таблицы решений) | ✅ | таблицы: тип задачи · ключевые решения · открытые вопросы/риски |
| Таблицы-эквиваленты диаграмм | ✅ (вместо Mermaid) | см. ниже |
| ADR | ✂️ компактный (если нетривиальное решение) | решение · причина · альтернатива · риск |
| Test Strategy | ✅ всегда | таблица (уровни · сценарии · граничные · не тестируем) |
| API-контракты (OpenAPI/AsyncAPI/md) | ✅ если меняется/добавляется API | code/spec, md-таблицы |
| dev-process-plan | ✅ обновляется | таблицы |
| Design Report (нарратив) | ➖ не создаётся | — |
| C4/DFD/SD/WF/BPMN/ERD (Mermaid) | ➖ не создаются | заменены таблицами |
| `docs/architecture.md` | ➖ не обновляется | — |

## Таблицы-эквиваленты диаграмм (замена Mermaid в `compact`)

| Вместо диаграммы | Таблица | Колонки |
|---|---|---|
| C4 C1/C2/C3 | Компоненты + связи | Компонент · Слой/Контейнер · Роль · Зависит от · Тип связи |
| DFD | Потоки данных | Источник · Процесс · Хранилище · Приёмник · Данные · Направление |
| Sequence | Шаги вызовов | Шаг · Актор · Вызывает · Сообщение/метод · Возврат |
| Workflow / BPMN | Переходы состояний | Состояние · Событие/условие · Действие · Следующее состояние |
| ERD | Сущности/атрибуты + связи (`skill.dev.ru.data-model-table`) | Сущность · Поле · Тип; Связь · Тип · Ключи |

Условия применимости таблиц — те же, что условия генерации соответствующих диаграмм в `skill.ai-sdlc.ru.phase-2-design` (создавать таблицу только когда создавалась бы диаграмма).

## Незыблемое (создаётся в обоих профилях)

Test Strategy, API-контракты (при изменении API), dev-process-plan.
