# Reference: расширенные примеры для таблицы модели данных

Этот файл содержит дополнительные примеры и краевые случаи для `skill.dev.ru.data-model-table`.
Используй его, когда базовых примеров из `SKILL.md` недостаточно.

## 1) Union / oneOf (REST/OpenAPI)

Контекст: поле может принимать одну из двух структур.

| N | Свойство модели | Наименование | Тип данных | Формат | Комментарий |
|---|---|---|---|---|---|
| 1 | `paymentMethod` | Способ оплаты | `CardPaymentDto \| BankTransferPaymentDto` | `oneOf` | Дискриминатор: `methodType` |
| 2 | `paymentMethod.methodType` | Тип способа | `string` | enum | `CARD`, `BANK_TRANSFER` |

Примечание: правила enum/discriminated union синхронизируй с `skill.dev.ru.enum-doc`.

## 2) Наследование (Entity/BaseEntity)

Контекст: доменная сущность наследует базовые поля аудита.

| N | Свойство модели | Наименование | Тип данных | Формат | Комментарий |
|---|---|---|---|---|---|
| 1 | `Id` | Идентификатор | `Guid` | GUID | (Inherited from BaseEntity) |
| 2 | `CreatedAt` | Дата создания | `DateTimeOffset` | ISO 8601 | (Inherited from BaseEntity) |
| 3 | `Status` | Статус заказа | `OrderStatus` | enum | |

Альтернатива: вынести `BaseEntity` в отдельную таблицу и оставить ссылку в комментарии.

## 3) Переход со Стратегии Б на A при росте вложенности

Контекст: ранее JSON имел глубину 3, затем добавился 4-й уровень.

- Было допустимо: `order.customer.address.city`.
- Стало глубже: `order.customer.address.location.coordinates.lat`.
- Действие: переведи всю таблицу на Стратегию A и больше не используй dot-path в этом документе.

## 4) Когда `Комментарий` можно оставить пустым

- Оставляй пустым только если у поля нет бизнес-ограничений/особых правил поведения.
- Заполняй обязательно, если есть:
  - обязательность при `Type?`,
  - диапазоны и ограничения, не помещающиеся в `Формат`,
  - вычисляемые/служебные поля,
  - ссылки на внешние артефакты (enum, базовая таблица, контракт).
