# Описание эндпоинта API

Стандарт документирования одного REST API эндпоинта. Применяется при составлении API-контрактов, интеграционных паспортов, OpenAPI-описаний и архитектурной документации.

**Фазы процесса:** основной сценарий — Phase 2 (Design); также применяется при обновлении интеграционных паспортов и архитектурных артефактов.

**Смежные скиллы:**
- `skill.integration.ru.api-rest-standards` — правила проектирования API (URL, методы, версионирование, коды).
- `skill.dev.ru.data-model-table` — формат таблицы для тела запроса / ответа.
- `reference.md` — полный пример, краевые случаи и частые ошибки.

**Приоритет:** явные инструкции пользователя → этот скилл → общая эвристика.

## Когда применять

- Документирование отдельного эндпоинта в API-контракте или интеграционном паспорте.
- Описание операций при проектировании или ревью API.
- Заполнение OpenAPI/Swagger-описания.

---

## Порядок заполнения

1. Назови операцию и добавь краткое описание цели (если операция нетривиальна).
2. Укажи HTTP-метод и путь по `skill.integration.ru.api-rest-standards`.
3. Заполни таблицу параметров; если параметров нет, явно укажи `—`.
4. Опиши `Content-Type` и тело запроса; при отсутствии тела явно укажи `—`.
5. Опиши `Content-Type` и тело ответа; при отсутствии тела явно укажи `—`.
6. Заполни таблицу статусов: для каждого кода укажи условие и тип тела ответа.

## Шаблон описания эндпоинта

### \<Название операции, например: Создание пользователя\>

\<Краткое описание операции: что делает, зачем нужна. 1–2 предложения. Опционально, но рекомендуется для нетривиальных операций.\>

#### Запрос

1. **HTTP-метод:** `<POST | GET | PUT | PATCH | DELETE>`
2. **Путь:** `<например, /api/v1/users/{userId}/contact>`
3. **Параметры:**

Допустимые значения колонки **«Тип параметра»**: `path`, `query`, `header`, `cookie` (см. справочник ниже).

*Пример заполнения:*

| N | Параметр | Тип параметра | Название | Тип данных | Формат | Комментарий |
|---|---|---|---|---|---|---|
| 1 | `userId` | `path` | Идентификатор пользователя | `string` | GUID | |
| 2 | `filter?` | `query` | Фильтр | `string` | — | Необязателен |
| 3 | `X-Request-Id` | `header` | Идентификатор запроса | `string` | GUID | Нестандартный заголовок |
| 4 | `locale?` | `cookie` | Локаль пользователя | `string` | RFC 5646 | Необязательный cookie |

*\<Если тело запроса отсутствует — раздел 4 и 5 пропускается.\>*

4. **Content-Type:** `<MIME тип, например, application/json>`
5. **Тело запроса:**

\<Таблица по `skill.dev.ru.data-model-table`\>

---

#### Ответ

1. **Content-Type:** `<MIME тип при наличии тела, например, application/json>`
2. **Тело ответа:**

\<Таблица по `skill.dev.ru.data-model-table`\>

3. **Статусы:**

*Пример заполнения — перечень статусов зависит от логики операции и может быть больше:*

| N | Статус | Условие | Тело ответа | Комментарий |
|---|---|---|---|---|
| 1 | `201` | Успешное создание | `UserDto` | |
| 2 | `401` | Отсутствует или невалиден токен доступа | `ErrorDto` | |
| 3 | `403` | Недостаточно прав для операции | `ErrorDto` | |
| 4 | `400` | Ошибка валидации входных данных | `ValidationErrorDto` | |
| 5 | `404` | Пользователь не найден | `ErrorDto` | |
| 6 | `409` | Пользователь с таким email уже существует | `ErrorDto` | |

> `500` обычно не фиксируется как отдельный бизнес-сценарий операции и описывается на уровне общего error-handling сервиса.

## Описание колонок

### Параметры запроса

| Колонка | Описание |
|---|---|
| **N** | Порядковый номер строки. |
| **Параметр** | Системное название параметра. Суффикс `?` означает необязательный параметр: `filter?`. |
| **Тип параметра** | Где передаётся параметр. Допустимые значения: `path`, `query`, `header`, `cookie`. |
| **Название** | Человекочитаемое описание. |
| **Тип данных** | Тип значения. Нотация — по `skill.dev.ru.data-model-table`. |
| **Формат** | Ограничения значений. Нотация — по `skill.dev.ru.data-model-table`. |
| **Комментарий** | Особенности, бизнес-правила. |

### Статусы ответа

| Колонка | Описание |
|---|---|
| **N** | Порядковый номер строки. |
| **Статус** | HTTP-код ответа. |
| **Условие** | Конкретное условие возврата этого статуса. Обязательно заполнять — без условия статус неинформативен. |
| **Тело ответа** | Тип возвращаемой модели (`UserDto`, `ErrorDto`) или `—` при отсутствии тела. |
| **Комментарий** | Особенности, ссылки на enum ошибок и т.п. |

> Первый столбец всегда `N`, последний всегда `Комментарий`.

## Типы параметров — справочник

| Значение | Пример в URL | Описание |
|---|---|---|
| `path` | `/api/v1/users/{userId}` | Элемент самого пути; `userId` — параметр пути |
| `query` | `/api/v1/users?page=1&size=20` | Следует после `?` |
| `header` | `X-Request-Id: <guid>` | Нестандартный заголовок запроса |
| `cookie` | `Cookie: locale=ru-RU` | Параметр, передаваемый через cookie; использовать только если это явно часть контракта эндпоинта |

> В таблицу параметров включай только endpoint-specific параметры. Стандартные HTTP-заголовки (`Authorization`, `Content-Type`, `Accept`) документируй на уровне сервиса/контракта.

## Связь с другими скиллами

- **Тело запроса / ответа** — описывается по `skill.dev.ru.data-model-table` (выбор стратегии A или Б, `?`-нотация nullable).
- **Коды статусов и HTTP-методы** — выбираются по `skill.integration.ru.api-rest-standards`.
- **Перечисление эндпоинтов сервиса** — ведётся в интеграционном паспорте (`docs/integrations/integration-passport.*.md`).
- **Краевые случаи и антипаттерны** — смотри в `reference.md`.

## Перед сдачей (чеклист)

- [ ] Назови операцию так, чтобы в названии отражалось действие (глагол + сущность или существительное-действие).
- [ ] Проверь, что HTTP-метод и путь соответствуют `skill.integration.ru.api-rest-standards`.
- [ ] Помечай необязательные параметры суффиксом `?` в колонке «Параметр».
- [ ] Используй в колонке «Тип параметра» только `path`, `query`, `header` или `cookie`.
- [ ] Описывай тела запроса и ответа таблицей по `skill.dev.ru.data-model-table`.
- [ ] Заполняй для каждого статуса колонки «Условие» и «Тело ответа».
- [ ] Не дублируй стандартные заголовки (`Authorization`, `Content-Type`, `Accept`) в таблице параметров.
- [ ] Сверяй коды ответов с `skill.integration.ru.api-rest-standards`.
