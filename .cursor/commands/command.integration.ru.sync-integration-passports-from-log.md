# Синхронизация integrations-log и паспортов интеграций

Команда для Cursor Agent: создать или обновить `integrations-log`, создать файлы паспортов по строкам лога, выполнить автопредзаполнение и при нехватке обязательных данных запустить интервьюирование.

---

## Как вызывать

Примеры пользовательского запроса:

- `Синхронизируй integrations-log и паспорта интеграций для модуля image-to-description-utility`
- `Выполни sync-integration-passports-from-log для всего репозитория`

Если модуль не указан, агент определяет модули автоматически по наличию `docs/`.

---

## Обязательный порядок работы

### 0. Подтвердить контекст интеграций

1. Применить правило `.cursor/rules/rule.integration.ru.integration-passport-and-reliability-gate.mdc`.
2. Сообщить пользователю, что обнаружены внешние интеграции, и что пользователь должен самостоятельно уведомить и согласовать интеграцию с архитекторами и ИБ.
3. Запросить у пользователя один вариант:
   - **Подтвердить и продолжить**;
   - **Отклонить добавление интеграции**;
   - **Приостановить обработку до дальнейших команд**.
4. Если пользователь выбрал:
   - **Подтвердить и продолжить** — продолжить команду и добавить в итог явную отметку подтверждения пользователя;
   - **Отклонить добавление интеграции** — остановить изменение/добавление интеграции и добавить в итог отметку об отклонении;
   - **Приостановить обработку** — приостановить выполнение команды до следующего явного запроса пользователя.

### 1. Синхронизировать технический журнал интеграций

1. Запустить:
   - `node .githooks/integration-passports.validate.mjs pre-push`

   > Используется режим `pre-push` (сканирует весь репозиторий + выставляет `Deleted At UTC` для исчезнувших интеграций).
   > Режим `pre-commit` (только staged-файлы) не подходит для полной синхронизации.

   **1а. Если скрипт выдал предупреждение `stack not detected`:**
   - Сообщить пользователю, что стек проекта не определён автоматически.
   - Запросить выбор из: `dotnet / nodejs / python / go / java / all`.
   - Повторно запустить: `node .githooks/integration-passports.validate.mjs pre-push --stack=<выбор>`.

2. Если скрипт создал или обновил `docs/integrations/integrations-log.<project-name>.md`, продолжить работу уже с новым содержимым.
3. Для каждого найденного `integrations-log` считать источником истины таблицу:
   - `Integration ID`
   - `Added At UTC`
   - `Last Seen At UTC`
   - `Deleted At UTC`
   - `Code Marker`
   - `Passport Path`

### 2. Создать или обновить файлы паспортов из integrations-log

Для каждой строки лога:

1. Если `Passport Path` отсутствует или не соответствует `integration-passport.{integration-name}.md`, исправить путь в логе.
2. Если файл паспорта не существует, создать его по шаблону:
   - `.agents/skills/skill.integration.ru.integration-doc/template.integration-passport.md`
3. Если файл существует, не перетирать вручную заполненные значения; обновлять только вычислимые поля.
4. Для `deleted`-интеграций (`Deleted At UTC` заполнен):
   - сохранить паспорт;
   - проставить статус `Выведено`;
   - добавить явную отметку о выводе из эксплуатации и запись в `Changelog`.

### 1.5 Заполнить Scope для записей с пустым Scope

После синхронизации лога для каждой активной записи с пустым `Scope`:
1. Показать пользователю: `Integration ID`, `Name`, `Stack`.
2. Запросить: `external` (внешняя система) или `internal` (внутри системы/межсервис).
3. Для детекторов `db-*` уточнить: «БД сервиса (internal) или внешняя БД (external)?»
4. Обновить поле `Scope` в integrations-log.
5. Для записей с `Scope = internal`: паспорт не создаётся.

### 3. Автопредзаполнение паспорта

После создания/обновления паспорта заполнить максимум доступных данных без выдумывания:

- `Название интеграции` <- человекочитаемое имя из `Integration ID`.
- `Внешняя система` <- из `Integration ID` и `Code Marker`.
- `Дата создания` <- дата из `Added At UTC` (формат `YYYY-MM-DD`).
- `Последнее обновление` <- текущая дата UTC.
- `Статус` <- `Разработка` для active, `Выведено` для deleted.
- `Репозиторий` <- имя текущего репозитория.
- `Внешние эндпоинты` и `Протокол/Формат` <- по сигнатурам в `Code Marker` и по обнаруженным вызовам в коде (REST/gRPC/GraphQL/Webhook/SOAP/SFTP/Queue).
- `Обработка ошибок` <- фактические timeout/retry/circuit breaker из кода/конфигурации, если они явно определены.

### 4. Проверка обязательных полей паспорта

Проверить, что для каждой active-интеграции заполнены обязательные поля:

1. `Название интеграции`
2. `Внешняя система`
3. `Владелец (бизнес)`
4. `Дата создания`
5. `Tier проекта`
6. `Статус`
7. `Направление`
8. `Протокол`
9. `Формат данных`
10. `Способ вызова`
11. `Метод аутентификации`
12. `Где хранятся credentials`
13. `Содержит персональные данные`

Также проверить, что в `Changelog` есть минимум одна заполненная запись с датой, автором и изменением.

### 5. Если обязательных данных недостаточно — запустить интервьюирование

Если хотя бы одно обязательное поле нельзя надежно заполнить по коду/логу:

1. Немедленно запустить процесс по скиллу:
   - `.agents/skills/skill.arch.ru.architecture-requirements-interviewer/SKILL.md`
2. Создать раунд вопросов в файле:
   - `.input/proposals/integration-passport-missing-fields-proposal.md`
3. Сформулировать пакет вопросов только по недостающим полям (3-7 вопросов за раунд).
4. Сообщить пользователю, что нужно заполнить файл и прислать явный сигнал завершения (`готово`, `раунд завершен`).
5. После сигнала пользователя:
   - перенести ответы в файл опроса (`interviewer-survey.md` в модуле);
   - обновить паспорта и связанные документы в `docs/`;
   - убедиться, что в `docs/` не добавлены ссылки на `.input/`.

---

## Критерии завершения команды

Команда считается выполненной, когда:

1. `integrations-log` синхронизирован с кодом и валиден по формату (9-колоночная схема).
2. Поле `Scope` заполнено для всех `active` записей (нет пустых значений).
3. Для `active` записей с `Scope = external` существуют актуальные `integration-passport.*.md`.
4. Для `active` записей с `Scope = internal` паспорт не создаётся.
5. Паспорта максимально автопредзаполнены по фактам из кода и лога.
6. Для `deleted`-интеграций сохранены паспорта и добавлена отметка вывода.
7. Если обязательных данных не хватает, создан файл интервью-раунда и пользователь получил инструкцию по дозаполнению.
