# Команда: генерация текста коммита по staged изменениям

Сгенерируй текст коммита для текущих staged изменений в репозитории.

## Шаги

1. Выполни `git diff --staged` — прочитай, что именно проиндексировано (только чтение, без `git add`).
2. Выполни `git log --oneline -10` — изучи стиль и язык последних коммитов.
3. Проанализируй staged изменения:
   - Определи **тип изменения** (`feat`, `fix`, `refactor`, `docs`, `chore`, `style`, `test`, `perf`, `ci`, `build`).
   - Определи **область** (`scope`) — конкретный модуль, папка или компонент (если применимо).
   - Выяви **суть изменения** в одном коротком предложении (imperative mood, английский).
   - Определи, нужно ли **тело** коммита (если изменений много или мотивация неочевидна).
4. Сформируй текст коммита по формату Conventional Commits:

```
<type>(<scope>): <короткое описание>

<тело — опционально, если изменение требует контекста>
```

## Правила формата

- Заголовок: до 72 символов; imperative mood («add», «fix», «update», не «added», «fixes»).
- Scope: одно слово или kebab-case; опускается, если изменение сквозное.
- Тело: отделяется пустой строкой; раскрывает **почему**, не **что** (что видно из diff).
- Не дублируй в теле то, что уже выражено заголовком.
- Не ссылайся на номера тикетов, если они не были даны пользователем.

## Вывод

Выведи **только готовый текст коммита** (без лишних пояснений), чтобы пользователь мог скопировать его целиком. Если изменения неоднородны и лучше разбить на несколько коммитов — предупреди об этом отдельной строкой после текста коммита.
