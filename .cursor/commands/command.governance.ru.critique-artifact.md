# Команда: критический разбор артефакта (скилл / команда / правило)

Критически оцени качество указанного артефакта по четырём блокам критериев.  
Выводи конкретные находки в формате «Проблема → Рекомендация» с уровнем серьёзности.

## Аргументы

`$ARGUMENTS` — путь к файлу или название артефакта (SKILL.md, `.cursor/commands/*.md`, `.cursor/rules/*.mdc`).  
Если путь не указан — попроси уточнить.

---

## Шаг 1: Определить тип и прочитать

1. По пути определи тип: **скилл** (`SKILL.md`), **команда** (`.cursor/commands/`), **правило** (`.cursor/rules/`).
2. Прочитай файл целиком. Если есть `reference.md` рядом — прочитай и его.

---

## Шаг 2: Оценить по четырём блокам

Для каждого блока собирай находки. Пропускай пункты, не применимые к данному типу.

### Блок А — Достоверность подходов

| Вопрос | На что смотреть |
|--------|----------------|
| Актуальность стека | Инструменты/паттерны не устарели; deprecated явно помечены с альтернативой |
| Внутренняя согласованность | Разделы не противоречат друг другу |
| Соответствие типу артефакта | Скилл описывает процесс, а не теорию; правило даёт однозначный запрет/требование |

### Блок Б — Соответствие best practice

| Вопрос | На что смотреть |
|--------|----------------|
| Реалистичность | Рекомендации применимы в реальных проектах без скрытых допущений |
| Покрытие краевых случаев | Нет нераскрытых «а что если» внутри скоупа артефакта |
| Согласованность с репозиторием | Нет конфликтов с `rule.security.en.corporate-dlp.mdc` и смежными артефактами |
| Разграничение must/should | «Должно» не смешивается с «предпочтительно» |

### Блок В — Применимость в LLM-разработке _(ключевой)_

| Критерий | Проблема-сигнал | Почему важно |
|----------|----------------|--------------|
| **Ясность формулировок** | Расплывчатые «по возможности», «при необходимости» без условий | LLM интерпретирует произвольно → неожиданный вывод |
| **Конкретные примеры** | Нет ни одного примера правильного/неправильного | Без примеров LLM галлюцинирует формат |
| **Шаблон вывода** | Ожидаемый формат результата не задан | LLM выдумывает структуру каждый раз |
| **Прогрессивное раскрытие** | Длинный `SKILL.md` без `reference.md` (>200 строк) | Большой контекст → медленнее, дороже, хуже фокус |
| **Повелительное наклонение** | «Агент должен делать X» вместо «Сделай X» | Пассивные формулировки снижают точность следования |
| **Чёткие триггеры** | Нет раздела «когда применять» / триггеры перекрывают другие артефакты | LLM применяет скилл не туда → тратятся токены впустую |
| **Фазовая регистрация** | Скилл фазово-специфичен, но не упомянут в «Используемые скиллы» соответствующего `phase-N` | LLM применяет скилл вне нужной фазы или пропускает его в нужной |
| **Чеклист завершения** | Нет финального чеклиста | LLM пропускает финальные шаги без явного «стоп-сигнала» |
| **Атомарность шагов** | Один шаг делает несколько несвязанных вещей | LLM плохо держит составные инструкции, выполняет частично |

### Блок Г — Структурная полнота (по `skill.governance.ru.authoring-high-quality-skills`)

Применяется в первую очередь к скиллам, частично к командам:

- [ ] Frontmatter: `name` (lowercase, дефисы, ≤64 символа) и `description` (третье лицо, английский, есть WHAT и WHEN)
- [ ] Вводный блок: скоуп, приоритет при конфликте, ссылки на сопутствующие файлы
- [ ] Логические H2-разделы (не одна «простыня»)
- [ ] Таблицы там, где сравниваются варианты
- [ ] Чеклист «Перед сдачей» (4–10 пунктов) или явное обоснование отсутствия
- [ ] Нет мёртвых ссылок на несуществующие файлы/пути

## Шаг 3: Сформировать отчёт

Выведи отчёт в следующем формате:

```
## Критический разбор: <имя артефакта> (<тип>)

### Блок А — Достоверность
  ✅ / ⚠️ ВАЖНО / ❌ КРИТИЧНО: <находка> → <рекомендация>

### Блок Б — Best practice
  ...

### Блок В — LLM-применимость
  ...

### Блок Г — Структурная полнота
  ...

---
### Итог

| Блок | Оценка | Главная проблема |
|------|--------|-----------------|
| А — Достоверность | 🟢 / 🟡 / 🔴 | ... |
| Б — Best practice | 🟢 / 🟡 / 🔴 | ... |
| В — LLM-применимость | 🟢 / 🟡 / 🔴 | ... |
| Г — Структура | 🟢 / 🟡 / 🔴 | ... |

### Приоритетные действия (топ-3)
1. ...
2. ...
3. ...
```

Если артефакт без критических замечаний — явно укажи это и не добавляй рекомендации ради количества.
