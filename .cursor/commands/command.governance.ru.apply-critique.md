# Команда: применение исправлений по результатам critique

Прочитай указанный critique-отчёт, извлеки все `❌ КРИТИЧНО` и `⚠️ ВАЖНО` находки, задай пользователю
все открытые вопросы единым блоком, затем составь план исправлений и **жди явной команды** — ничего не меняй без подтверждения.

## Аргументы

`$ARGUMENTS` — путь к critique-файлу (`.prompts-audit/critique/<slug>.md`).  
Опционально через пробел: буква блока для фильтрации (`А`, `Б`, `В`, `Г`).  
Примеры:
- `.prompts-audit/critique/skill.ai-sdlc.ru.phase-1-research.md`
- `.prompts-audit/critique/skill.ai-sdlc.ru.phase-1-research.md Г`

Если аргумент не передан — выведи: `Укажи путь к critique-файлу. Пример: .prompts-audit/critique/<slug>.md` и останови выполнение.

---

## Шаг 1: Прочитать critique-отчёт и определить целевой артефакт

1. Прочитай critique-файл целиком.
2. Из имени файла (без расширения) определи slug артефакта: `skill.*` → `.agents/skills/<slug>/SKILL.md`; `command.*` → `.cursor/commands/<slug>.md`; `rule.*` → `.cursor/rules/<slug>.mdc`.
3. Прочитай целевой артефакт. Если рядом есть `reference.md` — прочитай и его.
4. Если блок-фильтр задан (`А`/`Б`/`В`/`Г`) — на следующих шагах учитывай только находки из этого блока.

---

## Шаг 2: Извлечь находки и сформировать список

Собери все строки с `❌ КРИТИЧНО` и `⚠️ ВАЖНО` из отчёта.  
Пропускай `✅` — они не требуют действий.  
Пропускай строки раздела «Итог» и «Приоритетные действия» — извлекай только конкретные находки из блоков А–Г.

Для каждой находки зафиксируй:
- **Номер** (сквозной, начиная с 1)
- **Блок** (А / Б / В / Г)
- **Уровень** (КРИТИЧНО / ВАЖНО)
- **Суть** — одна фраза из текста находки
- **Целевой файл** — куда вносить изменение (SKILL.md, reference.md, новый файл и т. д.)
- **Статус** — `ясно` или `❓ вопрос: <текст>`

Находка считается неоднозначной, если:
- Сформулирована через «существенное», «при необходимости», «по возможности» без условий
- Требует выбора между несколькими вариантами реализации
- Ссылается на отсутствующий артефакт, назначение которого не описано в тексте

Если находок нет — выведи: `В отчёте не найдено КРИТИЧНО/ВАЖНО находок.` и останови выполнение.

Если **все** найденные КРИТИЧНО/ВАЖНО находки уже содержат суффикс `[RESOLVED ...]` — выведи:

```
✅ Все КРИТИЧНО/ВАЖНО находки в отчёте уже помечены [RESOLVED].

Что делать дальше?
  recheck   — запустить critique артефакта заново и обработать новые находки
  done      — завершить без изменений
```

**Жди ввода пользователя.** При `recheck` — прочитай целевой артефакт заново, запусти critique по `command.governance.ru.critique-artifact.md`, сохрани обновлённый critique в `.prompts-audit/critique/<slug>.md`, затем вернись к Шагу 2. При `done` — останови выполнение.

---

## Шаг 3: Задать все открытые вопросы единым блоком

Если есть находки со статусом `❓` — выведи их **все сразу** в следующем формате и жди ответов:

```
## ❓ Открытые вопросы — нужны ответы до составления плана

[1] (Блок В, #3) <суть находки>
Вопрос: <конкретный вопрос, без которого нельзя подготовить корректное исправление>

[2] ...

Ответь на каждый вопрос по номеру, например: «1 — <ответ>, 2 — <ответ>»
```

**Жди ответов. Не переходи к шагу 4 до получения явного ввода пользователя.**  
Если пользователь ответил не на все — уточни оставшиеся.

---

## Шаг 4: Составить план исправлений

После получения ответов на все вопросы сформируй план для каждой находки.

Для каждого исправления:
1. Укажи **намерение** — что именно меняется и почему.
2. Определи **действие**: изменить существующий файл / создать новый файл / переместить фрагмент.
3. Подготовь **описание изменения** прозой — структуру diff или содержимое нового файла.  
   Для изменений в существующем файле — укажи конкретное место (раздел / строку).
4. Оцени **риск**:
   - `low` — добавление нового раздела, уточнение формулировки, вынос шаблона в reference.md
   - `medium` — реструктуризация раздела, изменение директив агенту, переименование
   - `high` — удаление разделов, изменение frontmatter, структурный рефакторинг SKILL.md
5. Укажи **зависимости** — если исправление #2 требует сначала выполнить #1.

Выведи план строго в формате:

```
## План исправлений: <slug> [N исправлений]

---

### [1] Блок Г — КРИТИЧНО: <суть находки>
**Целевой файл:** `.agents/skills/.../SKILL.md`
**Действие:** изменить существующий файл
**Что меняется:** <прозой — добавить/изменить/удалить что именно и где>
**Риск:** low
**Зависит от:** —

---

### [2] ...
```

---

## Шаг 5: Ожидать подтверждения

После вывода плана выведи ровно следующее:

```
План готов. Введи команду:
  apply all       — применить все исправления
  apply 1, 3      — применить выбранные (по номеру)
  skip            — отменить, не вносить изменений
```

**Жди ввода пользователя. Ничего не меняй до получения явной команды.**

---

## Шаг 6: Применить подтверждённые исправления

После получения `apply ...`:

1. Применяй исправления **последовательно**, строго по номерам из подтверждения, с учётом зависимостей.
2. При создании нового файла (`reference.md`, новый раздел) — создай файл и добавь ссылку из `SKILL.md`.
3. Не трогай код и текст за пределами конкретного исправления.
4. После каждого исправления кратко сообщи: `[N] применено → <одна фраза что сделано>`.

---

## Шаг 7: Отметить исправления как решённые

После применения всех подтверждённых исправлений:

1. В critique-файле (`.prompts-audit/critique/<slug>.md`) добавь рядом с каждой применённой находкой суффикс ` — [RESOLVED yyyy-mm-dd]`.  
   Пример: `**⚠️ ВАЖНО: Шаблон занимает 53% тела.** ... — [RESOLVED 2026-05-14]`
2. Если **все** `❌ КРИТИЧНО` и `⚠️ ВАЖНО` находки в файле получили `[RESOLVED]` — обнови строку артефакта в `.prompts-audit/critique-report.md`: поставь статус `✅`, обнови поле «Главная проблема» на `Все критические замечания закрыты`, обнови «Дата» на текущую дату.
3. Если закрыты не все — оставь статус `⚠️`, обнови «Главная проблема» (убери закрытые из описания), обнови «Дата» на текущую дату.

> «Дата» обновляется **всегда** при применении любых исправлений — это отметка о том, что `apply-critique` обработал файл.

---

## Ограничения

- **Скиллы первичнее команд:** при расхождении между `SKILL.md` и командным файлом — исправляй командный файл на основе скилла, не наоборот.
- Структурный рефакторинг (`high`-риск, затрагивающий несколько файлов) — **только** при явном `CONFIRM: REWRITE` от пользователя.
- Соблюдай `rule.dev.ru.no-silent-rewrite-legacy-code.mdc`: хирургические изменения, без попутной «уборки».
- Агент **не стейджит файлы** (`git add`): изменения остаются unstaged согласно `rule.governance.ru.git-agent-no-staging`.
- Не агрегируй несколько `medium/high`-изменений в один шаг — применяй последовательно.
