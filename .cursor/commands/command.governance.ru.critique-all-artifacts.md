# Команда: Критический разбор всех артефактов репозитория

Последовательный четырёхблочный critique скиллов, команд и правил через `command.governance.ru.critique-artifact`.  
Каждый артефакт проверяется в **изолированном контексте** (сброс между артефактами); находки не переносятся.  
Результат по каждому артефакту — в отдельном файле `.prompts-audit/critique/{slug}.md`.

## Назначение

Систематически применяет critique (А — Достоверность, Б — Best practice, В — LLM-применимость, Г — Структурная полнота) ко всем артефактам репозитория.  
Команда фиксирует находки; исправления — отдельный шаг (вручную или другой командой).  
Сводный статус хранится в `.prompts-audit/critique-report.md`.

**Область применения:** `.agents/skills/`, `.cursor/commands/`, `.cursor/rules/`.  
**Приоритет при конфликте критериев:** `command.governance.ru.critique-artifact.md` имеет приоритет над любыми иными трактовками формата отчёта.

## Аргументы

- _(без аргументов)_ — продолжить: найти первый 🔲 и выполнить critique, затем остановиться.
- `--all` — пройти все непроверенные 🔲 подряд до конца без паузы.
- `--type skills|commands|rules` — обрабатывать только указанный тип артефактов.
- `--id S03` — выполнить critique конкретной строки по ID.
- `--init` — полностью пересоздать `.prompts-audit/critique-report.md`: заново просканировать папки и сбросить все статусы на 🔲. Существующие файлы в `.prompts-audit/critique/` при этом **не удаляются**; при совпадении slug файл будет перезаписан при следующей проверке.

## Шаг 0: Инициализация (если файл отсутствует или передан `--init`)

Перед запуском алгоритма проверь наличие `.prompts-audit/critique-report.md`.

**Если файл отсутствует или передан `--init`** — выполни полное пересканирование:

1. Просканируй `.agents/skills/` — найди все папки, содержащие `SKILL.md`. Каждая → строка в секции «Скиллы» (ID: `S01`, `S02`, …, `Вкл = ✅`, статус 🔲). **Строки сортируй по имени папки в алфавитном порядке.**
2. Просканируй `.cursor/commands/` — найди все `.md`-файлы. Каждый → строка в секции «Команды» (ID: `C01`, `C02`, …, `Вкл = ✅`, статус 🔲). **Строки сортируй по имени файла в алфавитном порядке.**
3. Просканируй `.cursor/rules/` — найди все `.mdc`-файлы. Каждый → строка в секции «Правила» (ID: `R01`, `R02`, …, `Вкл = ✅`, статус 🔲). **Строки сортируй по имени файла в алфавитном порядке.**
4. Создай `.prompts-audit/critique-report.md` по шаблону ниже.
5. Сообщи пользователю: сколько артефактов найдено по каждому типу.

**Если файл существует и `--init` не передан** — перейди к алгоритму.

### Шаблон файла отчёта

```markdown
# Critique-отчёт: скиллы, команды, правила

Сводная таблица критического разбора всех артефактов репозитория.
Каждый артефакт проверяется командой `command.governance.ru.critique-artifact` в изолированном контексте.
Детальный результат по каждому артефакту: `.prompts-audit/critique/{slug}.md`.

---

## Статусы

| Статус | Значение | Критерий |
|--------|----------|---------|
| 🔲 | Не проверен | — |
| ✅ | Без критических замечаний | Ни один блок не получил 🔴; нет находок с пометкой ВАЖНО/КРИТИЧНО |
| ⚠️ | Найдены проблемы | Хотя бы одно 🟡 или 🔴 в итоговой таблице critique |
| ❌ | Нечитаем | Файл не найден или не содержит читаемого содержимого |

## Столбец «Вкл»

| Значение | Смысл |
|----------|-------|
| ✅ | Включён — будет проверен (по умолчанию для всех строк) |
| ⏭️ | Пропущен — исключён из проверки (задан пользователем до запуска или командой skip в ходе сессии) |

---

## Скиллы

| # | Артефакт | Путь | Вкл | Статус | Дата | Главная проблема |
|---|----------|------|-----|--------|------|-----------------|
<строки S01, S02, … — заполни по результатам сканирования .agents/skills/>

---

## Команды

| # | Артефакт | Путь | Вкл | Статус | Дата | Главная проблема |
|---|----------|------|-----|--------|------|-----------------|
<строки C01, C02, … — заполни по результатам сканирования .cursor/commands/>

---

## Правила

| # | Артефакт | Путь | Вкл | Статус | Дата | Главная проблема |
|---|----------|------|-----|--------|------|-----------------|
<строки R01, R02, … — заполни по результатам сканирования .cursor/rules/>
```

Формат строки таблицы:
```
| S01 | <имя-папки-или-файла-без-расширения> | `<относительный-путь>` | ✅ | 🔲 | — | — |
```

## Алгоритм (один шаг / без аргументов)

1. Открой `.prompts-audit/critique-report.md`.
2. Найди первую строку со статусом 🔲 **и `Вкл = ✅`** (с учётом фильтра `--type` или `--id`, если переданы). Строки с `Вкл = ⏭️` пропускай — они исключены пользователем.
3. Выполни critique артефакта в изолированном контексте (см. раздел «Изоляция контекста»).
4. Сохрани полный текст critique в `.prompts-audit/critique/{slug}.md`.
5. Определи итоговый статус по критериям из шаблона отчёта (секция «Статусы»):
   - ✅ — ни один блок не получил 🔴; нет находок с пометкой ВАЖНО/КРИТИЧНО.
   - ⚠️ — есть хотя бы одно 🟡 или 🔴 в итоговой таблице.
6. Обнови строку в отчёте: статус, текущую дату, краткую главную проблему (или «—»).
7. Выведи сводку (см. «Формат вывода»).
8. **Остановись.** Пользователь подтверждает продолжение или вводит одну из команд:
   - Продолжить → перейди к следующей строке с 🔲 + `Вкл = ✅`.
   - «пропустить» / «skip» → установи `Вкл = ⏭️` для следующей 🔲-строки, затем переходи к той, что после неё (первая 🔲 + `Вкл = ✅`).
   - «все» / «all remaining» → переключись в режим `--all`: проверяй оставшиеся 🔲 + `Вкл = ✅` подряд без пауз до конца списка.

## Алгоритм `--all`

Тот же алгоритм без паузы: после каждого артефакта автоматически переходи к следующей строке с 🔲 + `Вкл = ✅`. Строки с `Вкл = ⏭️` пропускай.  
Останавливайся только при ошибке чтения файла:
- файл не найден / путь недействителен — эскалируй пользователю, затем переходи к следующему;
- файл найден, но не содержит читаемого содержимого — пометь строку статусом ❌ с примечанием «нечитаем», эскалируй и продолжи.

После обработки **последнего** 🔲 + `Вкл = ✅` артефакта выведи итоговую строку:
```
Все артефакты проверены. Итого: N ✅  M ⚠️  K ❌ (нечитаемые)  P ⏭️ (пропущены)
Для применения исправлений — command.governance.ru.apply-critique <slug> по каждому ⚠️.
```

## Изоляция контекста (сброс при каждой проверке)

Находки одного артефакта не должны влиять на оценку следующего.

Для каждого 🔲-артефакта выполняй последовательно:

1. **Определи путь к файлу** артефакта из столбца «Путь» в отчёте.
   - Для скилла: путь к `SKILL.md` внутри папки. Если рядом есть `reference.md` — зафиксируй и его путь.
   - Для команды / правила: путь к самому файлу.

2. **Сформируй промпт для sub-agent**, подставив `{path}` и (при наличии) `{reference_path}`:
   ```
   Выполни критический разбор артефакта по четырём блокам (А — Достоверность,
   Б — Best practice, В — LLM-применимость, Г — Структурная полнота).

   Файл для проверки: {path}
   [Сопутствующий reference: {reference_path}]   ← включать только если существует

   Инструкция для разбора: .cursor/commands/command.governance.ru.critique-artifact.md
   Эталон качества: .agents/skills/skill.governance.ru.authoring-high-quality-skills/SKILL.md

   Прочитай файл(ы) целиком, выполни critique по всем блокам и верни полный текст
   отчёта: блоки А–Г с находками, итоговая таблица, топ-3 приоритетных действия.
   Не сокращай и не резюмируй.
   ```

3. **Запусти sub-agent** с этим промптом как единственным вводом. Не передавай историю предыдущих critique, список уже проверенных артефактов или накопленные наблюдения из текущей сессии.

4. **Получив результат**, сохрани его в `.prompts-audit/critique/{slug}.md` и обнови строку в отчёте.

**Slug-правило:**
- Скилл: имя папки. Пример: `skill.arch.ru.c4-diagrams`.
- Команда: имя файла без расширения `.md`. Пример: `command.governance.ru.critique-artifact`.
- Правило: имя файла без расширения `.mdc`. Пример: `rule.governance.ru.incremental-governance-edits`.

## Компактирование контекста главного агента

После сохранения critique в файл и обновления строки в отчёте главный агент **не должен удерживать полный текст critique в рабочем контексте** — он уже персистирован в `.prompts-audit/critique/{slug}.md`.

### Что сохранить в контексте
- Путь к отчёту: `.prompts-audit/critique-report.md`
- Краткий список обработанных ID текущей сессии (например: `S01 ⚠️, S02 ✅`)
- ID следующего артефакта к обработке

### Что сбросить
- Полный текст sub-agent critique по уже проверенным артефактам
- Находки и рекомендации по предыдущим артефактам
- Промпты sub-agent предыдущих итераций

### Правило для `--all` (длинные очереди)
При обработке очереди >10 артефактов главный агент компактирует контекст каждые 5 итераций: выводит строку вида
```
[Compact] Обработано: S01–S05 (✅×3 ⚠️×2). Продолжаю с S06.
```
и сбрасывает детальный контекст предыдущих итераций. Информация не теряется — она в файлах.

## Формат вывода

Шаблон строки вывода после каждого артефакта:

```
[{ID}] {slug} — {статус_emoji} {статус_текст}
      [Главная: {краткая_проблема}]          ← только при ⚠️
      [Блоки: А {цвет} | Б {цвет} | В {цвет} | Г {цвет}]   ← только при ⚠️
      Файл: .prompts-audit/critique/{slug}.md
      [→ Продолжить? «пропустить» / «skip» — пропустить следующий. «все» / «all remaining» — без пауз до конца.]  ← только в режиме без --all
```

Примеры:

```
[S03] skill.arch.ru.sequence-diagrams — ✅ Без критических замечаний
      Файл: .prompts-audit/critique/skill.arch.ru.sequence-diagrams.md
      → Продолжить? Или «пропустить» / «skip» для следующего.

[S04] skill.arch.ru.workflow-diagrams — ⚠️ ПРОБЛЕМЫ
      Главная: отсутствует шаблон вывода (Блок В), нет чеклиста завершения
      Блоки: А 🟢 | Б 🟡 | В 🔴 | Г 🟡
      Файл: .prompts-audit/critique/skill.arch.ru.workflow-diagrams.md
      → Продолжить? Или «пропустить» / «skip» для следующего.

[S05] skill.arch.ru.bpmn-diagrams — ⏭️ ПРОПУЩЕН по запросу пользователя
      → Продолжить? Или «пропустить» / «skip» для следующего.
```

## Критерии завершения (DoD)

- [ ] Все строки с `Вкл = ✅` имеют статус ✅, ⚠️ или ❌ (нет 🔲 среди включённых).
- [ ] Строки с `Вкл = ⏭️` учтены как намеренно пропущенные и не влияют на критерий завершения.
- [ ] Для каждого проверенного артефакта (`Вкл = ✅`) создан файл `.prompts-audit/critique/{slug}.md`.
- [ ] В отчёте заполнены столбцы «Дата» и «Главная проблема» для всех проверенных строк.
- [ ] Пользователь уведомлён об итогах: общее количество ✅ / ⚠️ / ❌ / ⏭️.
- [ ] Исходные файлы в `.agents/skills/`, `.cursor/commands/`, `.cursor/rules/` **не изменены**: команда только читает артефакты и создаёт файлы в `.prompts-audit/`. Правки вносятся отдельно через `command.governance.ru.apply-critique`.

## Чеклисты структурной валидации

Используются sub-agent при оценке блока Г (Структурная полнота).

### SKILL.md

- [ ] Frontmatter заполнен: `name` и `description` соответствуют содержимому
- [ ] Есть раздел «Когда применять» с конкретными триггерами
- [ ] Раздел «Границы» / «Когда НЕ применять» актуален — ссылки на другие скиллы не устарели
- [ ] Примеры присутствуют и отражают реальный вывод
- [ ] Есть чеклист «Перед сдачей» или явное обоснование его отсутствия
- [ ] Нет мёртвых ссылок: все `[text](path)` ведут к существующим файлам
- [ ] Именование файла соответствует `rule.governance.ru.cursor-skill-command-rule-filenames.mdc`

### Команды (`.cursor/commands/`)

- [ ] Заголовок H1 и описание назначения присутствуют
- [ ] Шаги пронумерованы и охватывают полный сценарий
- [ ] Все упомянутые скиллы существуют в `.agents/skills/`
- [ ] Выходные артефакты (файлы, папки) чётко названы
- [ ] Аргументы / варианты вызова описаны (если применимо)

### Правила (`.cursor/rules/`)

- [ ] Условия срабатывания однозначны, не дублируют другие правила
- [ ] Правила атомарны: каждое требует одного конкретного действия или запрета
- [ ] Нет конфликтов с `rule.security.en.corporate-dlp.mdc` (приоритет № 1)
- [ ] Все пути к файлам существуют (если правило ссылается на конкретные файлы)
