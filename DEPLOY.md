# Развёртывание

Операционный документ. Описание продукта — в `README.md`, архитектура — в `docs/architecture.md`.

## Сервисы

| Сервис | Образ | Порт | Что делает |
|---|---|---|---|
| `app` | сборка из `Dockerfile` (multi-stage, `node:22-alpine`) | `3000` | Приложение: интерфейс, API-роуты, агенты |
| `db` | `postgres:16-alpine` | `5432` | Каталог, партии, заказы, сад, вопросы |

Оба порта объявлены короткой формой, без привязки к хосту: маршрутизацию делает платформа.

## Переменные окружения

Задаются в интерфейсе платформы (раздел Environment). В репозитории значений нет.

| Имя | Тип | Пример | Назначение |
|---|---|---|---|
| `POSTGRES_PASSWORD` | required | — | Пароль пользователя PostgreSQL. Без него compose не стартует |
| `POSTGRES_DB` | optional | `nursery` | Имя базы |
| `POSTGRES_USER` | optional | `nursery` | Пользователь базы |
| `DATABASE_URL` | авто | `postgres://nursery:...@db:5432/nursery` | Собирается в compose из трёх переменных выше; задавать вручную не нужно |
| `LLM_PROVIDER` | optional | `rules` | `rules` — детерминированный режим без сети, `http` — внешняя модель |
| `LLM_BASE_URL` | optional | — | Адрес внешней модели; не нужен при `rules` |
| `LLM_API_KEY` | optional | — | Ключ внешней модели; не нужен при `rules` |
| `LLM_MODEL` | optional | — | Имя модели; не нужно при `rules` |
| `UPLOAD_DIR` | авто | `/app/uploads` | Каталог фото; задан в образе, указывает на именованный том |
| `APP_TIMEZONE` | optional | `Europe/Moscow` | Единый часовой пояс продукта |
| `SEED_ON_START` | optional | `true` | Наливать ли демо-данные в пустую базу при старте |

Значение по умолчанию `LLM_PROVIDER=rules` выбрано намеренно: стенд поднимается и работает без доступа к внешней модели.

Файл `.env.example` в репозитории отсутствует — его создание блокирует правило доступа агента к маске `.env.*`. Таблица выше заменяет его: список имён полный.

## Volumes

| Том | Что хранит | Потеря при удалении |
|---|---|---|
| `db-data` | Данные PostgreSQL | Каталог, заказы, сады, вопросы. Восстанавливается сидом с нуля |
| `uploads` | Фото к вопросам консультанту | Только загруженные снимки |

Оба тома именованные. Пути вида `./` не используются: платформа стирает каталог репозитория при каждом развёртывании.
Демо-данные восстанавливаются сами: сид идемпотентен и наливает их только в пустую базу.

## Healthcheck

| Сервис | Проверка | Интервал |
|---|---|---|
| `app` | `wget -qO- http://127.0.0.1:3000/health` → `{"ok":true,"db":"up"}` | 30 с, старт-период 40 с, 3 попытки |
| `db` | `pg_isready` | 10 с, 5 попыток |

`/health` проверяет три вещи: само приложение, соединение с базой и **наличие схемы** — запрос идёт к таблице `plants`, а не `select 1`. Ответы:

| Тело | Код | Что значит |
|---|---|---|
| `{"ok":true,"db":"up"}` | 200 | База отвечает, таблицы на месте |
| `{"ok":false,"db":"no-schema"}` | 503 | База отвечает, но таблицы `plants` нет — миграции не отработали |
| `{"ok":false,"db":"down"}` | 503 | Соединения нет |

На любой 503 контейнер уходит в unhealthy. Проверка схемы появилась после инцидента 11.09: схему снесли вручную, контейнер не перезапустили, `select 1` был зелёным при пустой базе — `memory/mistakes/2026-09-11-shema-snesena-kontejner-ne-perezapushchen.md`.

Адрес — именно `127.0.0.1`: busybox-wget в alpine резолвит `localhost` через DNS и падает.

## Локальный запуск

```bash
docker compose up --build
```

Симуляция того, как запускает платформа (переменные хоста не пробрасываются):

```bash
env -i PATH="$PATH" docker compose up --build
```

Проверка после старта:

```bash
curl -s 127.0.0.1:3000/health
curl -s '127.0.0.1:3000/api/catalog/plants?light=shade'
```

Без Docker: локальный PostgreSQL, затем `npm run db:migrate && npm run db:seed && npm run build && npm start`.

## Развёртывание на стенде

1. Репозиторий и проект заводит администратор платформы; ветка — `master`, сборка по `docker-compose.yml` в корне.
2. Задать переменные в разделе Environment. Обязательна одна: `POSTGRES_PASSWORD`.
3. Включить изолированное развёртывание в разделе Advanced.
4. Развернуть, дождаться зелёного статуса обоих сервисов.
5. Добавить домен: сервис `app`, контейнерный порт `3000`. **После добавления домена развернуть повторно** — метки маршрутизации проставляются в момент развёртывания.
6. Проверить `/health` по внешнему адресу.

Не отключать репозиторий от проекта и не менять настройки провайдера git.

## Кто гарантирует схему

Миграции и сид выполняет **только `docker-entrypoint.sh`** при старте контейнера `app`: `migrate.cjs` → `seed.cjs` (если база пустая) → `server.js`. Внутри самого приложения миграций нет — решение и причины в `memory/mistakes/2026-09-11-…` и в README.

Из этого следует правило, которое нельзя обойти: **любая ручная операция с базой стенда завершается пересозданием контейнера `app`**. В Dokploy это **Rebuild**, не Deploy: Deploy без изменений кода контейнер не пересоздаёт, entrypoint не выполняется, схема остаётся такой, какой её оставили руками.

Если пересоздать нельзя — накатить руками из контейнера:

```bash
docker exec -it <app> sh -c 'cd /app && node dist/migrate.cjs && node dist/seed.cjs'
```

## После деплоя, руками

Зелёный healthcheck — не доказательство. Четыре шага, две минуты, по внешнему адресу:

1. `/health` → `{"ok":true,"db":"up"}`. Любой другой ответ — стоп, смотреть лог.
2. `/api/catalog/plants` → непустой `items`, у растений заполнен `photoUrl`.
3. Главная → любая карточка каталога с фотографией → кружок в шапке открывает список из четырёх пользователей.
4. Низ лога `app` (`docker logs --tail 20 <app>`): время текущее, есть `миграции применены`, есть строка о сиде — `демо-данные` или `сид пропущен: база не пустая`.

Пока эти четыре шага не пройдены, состояние называется «задеплоено», а не «проверено на стенде».

## Диагностика

| Симптом | Причина | Что делать |
|---|---|---|
| Красный статус | Контейнер не поднялся | Открыть журнал развёртывания, смотреть конец лога |
| 404 при верном домене | Контейнер unhealthy | Проверить `/health`; чаще всего недоступна база |
| Bad Gateway | Неверный контейнерный порт в домене | Указать `3000` |
| Таймаут | Домен добавлен, но развёртывание не повторено | Развернуть ещё раз |
| `POSTGRES_PASSWORD` не задан | Compose останавливается на подстановке | Задать переменную в Environment |
| Данные пропали после развёртывания | Использован путь репозитория вместо тома | Проверить, что тома именованные |

## Ресурсы

Ориентир для песочницы: `app` — 0.5 CPU и 512 МБ (пик при сборке выше, сборка идёт на стороне платформы); `db` — 0.25 CPU и 256 МБ. Изменение лимитов — через администратора платформы.
