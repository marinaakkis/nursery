# Verify gate: готово — значит запущено и проверено

Самоотчёт агента «я реализовал» доказательством не является. Доказательство — работающий процесс и зафиксированный результат.

## Уровни

| Уровень | Что | Доказательство |
|---|---|---|
| 0. Статика | линтер, типы, тесты | вывод `check.sh` без ошибок |
| 1. Запуск | сервис поднимается с нуля по README | лог старта, время до готовности |
| 2. Сценарии | каждый критерий приёмки прогнан на живом сервисе | таблица AC → результат |
| 3. Инварианты | конкуренция, дубли, права — проверены параллельными запросами / скриптом | вывод скрипта |
| 4. UX | чек-лист из `ux-ui` на живом фронте | отмеченный чек-лист + скриншоты состояний |
| 5. Деплой | работает по внешнему URL | URL + скриншот |

Готово = все применимые уровни пройдены.

## Четыре состояния кода — до любой runtime-проверки

Частый провал раньше runtime: изменение не ушло из рабочего дерева, а агент докладывает «готово». Поэтому слово «готово» заменяется на положение в цепочке:

| Состояние | Как проверить | Если нет — как называть |
|---|---|---|
| в коммите | `git status` чистый | «написано, не закоммичено» |
| в `master` | `git log origin/master..HEAD` пустой | «закоммичено, не запушено» |
| на стенде | деплой прошёл, контейнеры healthy | «запушено, деплой не прошёл» |
| проверено на стенде | главный сценарий по внешнему URL | «задеплоено, не проверено» |

Отчёт называет **самое раннее незакрытое состояние**, а не самое далёкое закрытое.

## Шаги

1. `check.sh` (линтер + типы + тесты). Красное — стоп.
2. Поднять с чистой БД строго по README. Понадобился шаг не из README — дописать README.
3. Заполнить `docs/verify.md`:

```
# Verify — <дата/время>
## Запуск
команда: … · результат: … · время: …
## Критерии приёмки
| AC | Как проверял | Результат | Доказательство |
## Инварианты
| Инвариант | Метод | Результат |
## UX чек-лист
docs/ux.md, отмечено N/M, скриншоты в docs/screens/
## Деплой
URL: … · проверено: …
## Не пройдено / известные проблемы
```

4. Обновить `memory/services/<name>.md`: стенд, URL, версия — в той же сессии.
5. Всё непройденное — либо чинится, либо явно пишется в «известные проблемы». Скрывать нельзя: на защите спросят.

## Типовые обманки

- «Тесты проходят» — но теста на главный инвариант нет
- «Работает локально» — но в контейнере нет env-переменной
- «Форма отправляется» — но при ошибке сервера ничего не показывает
- «Реализовал бронирование» — но два параллельных запроса на одно место оба возвращают 200
