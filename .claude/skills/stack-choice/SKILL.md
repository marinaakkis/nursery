# Stack choice: стек под задачу

Оценщики проверяют гибкость. Ответ «потому что мы так умеем» — не аргумент. Ответ «потому что у задачи свойство X, и этот стек закрывает его дешевле» — аргумент.

## Шаги

1. **Выписать определяющие свойства задачи** (3–5 штук). Примеры: транзакционность и конкуренция за ресурс; реалтайм; тяжёлый UI; интеграции; срок 1,5 дня; деплой в конкретную инфраструктуру.
2. **Для каждого слоя** (бэк, БД, фронт, деплой) выписать 2–3 кандидата и оценить по таблице.
3. **Выбрать и записать** `memory/decisions/0001-stack.md` (шаблон уже лежит).
4. **Проверить на удобство для агента**: популярный стек с большим корпусом примеров → агент ошибается реже. Экзотика оправдана только если свойство задачи этого требует.

## Таблица оценки кандидата

| Критерий | Вопрос |
|---|---|
| Соответствие свойствам | Закрывает ли главное свойство задачи нативно (а не костылём)? |
| Скорость до рабочего прототипа | Сколько часов до первого запущенного сценария? |
| Агентопригодность | Хорошо ли агент знает стек; есть ли типизация, линтер, тесты «из коробки»? |
| Деплой | Ложится ли в целевую инфраструктуру без плясок (контейнер, статика)? |
| Риск | Что сломается первым и насколько это заметно на демо? |

## Ориентиры по типовым свойствам

| Свойство задачи | Что это требует | Не подходит |
|---|---|---|
| Конкуренция за ресурс (места, слоты, остатки) | Реляционная БД с транзакциями и уникальными индексами | Документные БД, in-memory без блокировок |
| Реалтайм (чат, live-статусы) | WebSocket/SSE, серверная модель событий | Чистый REST с поллингом «на глазок» |
| Много форм и таблиц | Готовая UI-библиотека, типизированный фронт | Ручная вёрстка с нуля |
| Контент-сайт, мало логики | Static-first, SSG, минимум бэка | Полноценный SPA + API |
| Интеграции с внешними API | Язык с зрелыми SDK, очереди для ретраев | — |
| 1,5 дня и демо | Один репозиторий, один процесс, SQLite/Postgres в контейнере | Микросервисы, очереди, кэш-слои |
| Деплой в контейнерную платформу (см. внутренний скилл деплоя) | Стек, который собирается в Docker multi-stage, слушает 0.0.0.0, отдаёт `/health` | Стек без нормального контейнерного образа, платформенно-зависимые рантаймы |

## Что записать в ADR-001

- Свойства задачи → требования к стеку
- Кандидаты по слоям и почему отвергнуты
- Выбор и главный риск выбора
- 🔶 если выбор отличается от привычного стека команды — сказать это явно: это плюс на защите
